# День 3: готовность стенда перед занятием

Это памятка преподавателю, не материал участника и не часть ZIP тетради.
Сайт и презентация не управляют токенами и не подтверждают сетевую доступность.

Перед занятием проверьте сроки персональных доступов через панель преподавателя,
обновите истёкшие токены и выдайте необходимые права чтения. Значения токенов и
статусы конкретных мест в репозитории сайта не сохраняются. Токены, базу и права
при обновлении сайта не читали и не меняли.

Код стенда уже содержит whoami/list_assignments/get_assignment, в отличие от
устаревшей памятки исходного черновика презентации. После изменения кода сервер
нужно перезапустить, затем обновить каталог инструментов клиента.

Адрес из конфигурации пользователя: http://192.168.0.106:8765/mcp.
Проверка http://192.168.0.106:8765/healthz с компьютера подготовки 8 ноября
закончилась тайм-аутом. IP не подтверждён как действующий. Перед раздачей сверьте
IPv4 компьютера преподавателя, общую сеть и TCP 8765. С клиентского ноутбука
проверьте healthz, подключение и все шесть диагностических пунктов. localhost
ученика не является адресом преподавателя. Host/Origin не отключать.

Авторизация — Authorization: Bearer <персональный токен>, один пробел. Ввод в
защищённых настройках, не в чат и не в проект. HTTP используйте только в доверенной
учебной сети; публичную доступность и защищённость этим не считаем проверенными.

Нужны mail:read, notes:read, assignments:read. Права записи выдаются отдельно только
для планируемых операций. Первоначальная диагностика ничего в базе не создаёт.
Проверьте VISIT-101–VISIT-105 и NOT_FOUND для TEST-999, не создавая TEST-999.
Если метка whoami чужая, остановить работу до чтения чужих данных.

Текущий mail_send — виртуальная почта своей песочницы. delivered_virtual не
подтверждает межучастниковую и внешнюю email-доставку. Для парного обмена нужна
отдельно подготовленная и проверенная функция; иначе практика заканчивается
черновиком. Разрешённый адресат — из справочника @severprom.test, request_id — UUID.
При неясном результате нельзя вслепую создавать новое письмо с новым request_id.

На сайте пример ответа со слайда 22 и подозрительное письмо явно названы примерами,
а не результатами MCP. Не выдавайте пример за доказательство работающего обмена.
Перед показом обновите ГОТОВНОСТЬ-СТЕНДА.md презентации и описание профиля на слайде 14:
там сведения о whoami и поручениях отстают от кода. Презентацию в этой задаче не меняли.
